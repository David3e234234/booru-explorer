# Booru Explorer

[![Live Demo](https://img.shields.io/badge/Live%20Demo-Vercel-000000?style=flat-square&logo=vercel&logoColor=white)](https://booru-explorer-kappa.vercel.app)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg?style=flat-square)](https://opensource.org/licenses/MIT)

Booru Explorer это веб-клиент для поиска, просмотра и каталогизации медиа с Booru-бордов и архивов платных подписок. Приложение работает как локальный или LAN-сервис: собственный frontend, серверный кэш медиа, авторизация, синхронизация лайков и избранного.

Демо: [booru-explorer-kappa.vercel.app](https://booru-explorer-kappa.vercel.app). На Vercel хранилище эфемерное, поэтому аккаунты и данные не сохраняются между перезапусками.

## Возможности

- **Источники:** Danbooru, Gelbooru, Rule34, Yande.re, Konachan, Safebooru, Rule34Video, Xbooru, Hypnohub, TBIB, Kemono и Pawchive.
- **Мульти-поиск:** один источник, все источники или собственная подборка с объединением выдачи.
- **Фильтры:** рейтинг, тип медиа, телосложение, теги, AI-контент, черный список, скрытие отдельных категорий.
- **Посты и альбомы:** группировка многостраничных публикаций, переключение страниц в просмотрщике, лайки и избранное.
- **Архивы:** инспекция ZIP, предпросмотр файлов, поиск облачных ссылок и паролей, скачивание отдельных файлов и серверная распаковка в галерею.
- **Видео:** превью через FFmpeg, полноэкранный просмотр, выбор качества, серверный транскод и локальный кэш.
- **Авторы:** отслеживание по авторам, персональная лента и рекомендации на основе лайков и исключений.
- **Аккаунты:** регистрация, вход, серверное хранение настроек и коллекций, экспорт и импорт данных.
- **Сеть:** индивидуальные HTTP, HTTPS и SOCKS5 прокси, публикация через LocalTunnel, резервные копии в Telegram.
- **Интерфейс:** русский и английский, три темы, PWA, управление с клавиатуры и мобильная адаптация.

## Требования

- Node.js `22.19.0` или новее
- npm
- FFmpeg в `PATH` для превью видео и транскодирования
- Windows, Linux или macOS

FFmpeg необязателен. Без него сервер отдает SVG-заглушку для превью, а запрос транскодирования завершается ошибкой `503 FFmpeg недоступен на сервере`.

## Установка и запуск

```bash
git clone https://github.com/David3e234234/booru-explorer.git
cd booru-explorer
npm install
npm start
```

По умолчанию сервер слушает порт `3000`. Если порт занят, приложение выбирает следующий свободный.

Другие команды:

```bash
node server.js --no-open          # запуск без открытия браузера
node server.js --port=3100        # явный порт
start_phone.bat                   # Windows: LAN-доступ и QR-код
```

Интерфейс: `http://localhost:3000`.

## Проверка и тесты

```bash
npm test              # unit, parser и integration suites
npm run test:unit
npm run test:integration
npm run verify         # алиас npm test
```

Тесты используют отдельный временный каталог `data`, не изменяют пользовательские настройки и не очищают рабочий медиакэш.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `PORT` или `SERVER_PORT` | Порт сервера |
| `BOORU_DATA_DIR` | Каталог данных, кэша и аккаунтов |
| `SESSION_SECRET` | Секрет подписи токенов. Рекомендуется задать в окружении |
| `BOORU_ADMIN_TOKEN` | Секрет владельца для server-wide операций, передается в `x-booru-admin-token` |
| `DANBOORU_LOGIN`, `DANBOORU_API_KEY` | Учетные данные Danbooru по умолчанию |
| `GELBOORU_USER_ID`, `GELBOORU_API_KEY` | Учетные данные Gelbooru по умолчанию |
| `RULE34_USER_ID`, `RULE34_API_KEY` | Учетные данные Rule34 по умолчанию |

Если `BOORU_ADMIN_TOKEN` не задан, владельцем считается первый зарегистрированный пользователь. Если токен задан, операции очистки кэша, прокси-теста, туннеля, бэкапа и server-download открываются по заголовку `x-booru-admin-token` без сессии. Клиент хранит токен оператора в `localStorage` под ключом `booru_admin_token_v1` и удаляет его при выходе из аккаунта.

## Хранение данных

По умолчанию данные находятся в `data/`:

- `settings.json` и пользовательские настройки
- `favorites.json`, `likes.json`, `dislikes.json`
- `favorite_authors.json`
- `users.json` и `users/<id>/`
- `cache/thumbnails`, `cache/videos`, `cache/archives`

`data/` не отслеживается Git. Пример публичных настроек находится в `data/settings.example.json`.

Резервная копия в Telegram создается как JSON-документ. Перед отправкой из него удаляются API-ключи, пароли, session-токены, прокси и пароли архивов.

## Сеть и безопасность

Сервер по умолчанию доступен другим устройствам в локальной сети, поэтому его нельзя считать доверенной средой без аутентификации.

- Запросы с чужим `Origin` блокируются.
- Устанавливаются CSP, `X-Content-Type-Options`, `X-Frame-Options` и `Referrer-Policy`.
- URL, полученные от пользователя, проходят SSRF-проверку.
- Медиапрокси отдает только растровые изображения, видео и аудио, но не HTML или SVG.
- FFmpeg получает уже проверенный локальный временный файл, а не удаленный URL.
- Пароли хешируются через `scrypt`, токены отзываются при выходе, а экспорт аккаунта не содержит password hash.
- Не публикуйте порт напрямую в интернет без HTTPS, firewall и ограничения доступа.

## Развертывание

Workflow `.github/workflows/deploy.yml` выполняет `npm test` перед SSH-деплоем на Alwaysdata. Push в `main` или `master` после успешной проверки перезапускает Passenger.

Для Vercel используется `vercel.json`. В serverless-режиме `DATA_DIR` перенаправляется в `os.tmpdir()`, поэтому файлы не переживают холодный старт.
